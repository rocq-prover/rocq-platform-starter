# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- CI: `gofmt` check across the `shared`, `linux`, `macos` and `windows` modules.
- CI: `go test` now runs for every module (previously the existing tests were
  never executed).
- CI: check that `*/embedded/manifest/latest.json` and `*/embedded/templates/*`
  match the repository source of truth (`manifest/latest.json`, `templates/`).

### Changed

- Resynchronized the embedded assets of the `macos` and `windows` modules, which
  were missing the manifest `docker` section.
- README: dropped `jq` and `curl` from the prerequisites (leftovers from the Bash
  installer; the Go applications use `net/http` and never shell out to either),
  and stated that opam is not installed automatically.
- Repository URLs in the README now point at the `rocq-prover` organisation.

### Removed

- The legacy Bash installer: `install.sh`, `install.ps1` (an unimplemented stub),
  `lib/*.sh`, and the `shell-installer` CI job. The Go applications are now the
  only installation path. The opam activation scripts written into the workspace
  are generated by `shared/workspace.WriteActivationScripts` and were never
  sourced from `lib/`.
- `windows/build`, an exact duplicate of `windows/build.sh`.

### Fixed

- Formatting of `shared/gui/stepchecklist.go`, `linux/internal/manifest/manifest.go`,
  `linux/internal/releases/releases_test.go` and `macos/internal/installer/installer.go`.

## [1.2.0] - 2026-09-07

### Added

- Docker installation method on Linux: pulls a pre-built Rocq Platform image from
  GHCR, generates a `.devcontainer/devcontainer.json` in the workspace and
  configures VSCode for "Reopen in Container".
- Manifest `docker` section describing the registry, tag, container user,
  `vsrocqtop` path and the available image variants (`ide`, `extended`, `full`).
- `scripts/generate-devcontainer.sh` to regenerate `.devcontainer/devcontainer.json`
  from the manifest.
- Release pipeline: macOS `tar.gz` artifact for the external signing pipeline.

### Fixed

- `vsrocqtop` was not installed in some configurations.

### Changed

- Removed the repository section from the README.

## [1.1.0] - 2026-04-23

### Changed

- Renamed the project from `rocq-bootstrap` to `rocq-platform-starter`.
- Updated the project status badge in the README.

### Fixed

- Crash when opening the doctor window for the first time.

## [1.0.0] - 2026-04-13

### Added

- Documentation, README and screenshots.
- macOS signing pipeline, triggered manually.

### Changed

- Reduced code duplication across the three installers by extracting the
  `shared` module.

### Fixed

- macOS dark mode environment issue.
- Ordering of the release list.

## [0.1.0-beta] - 2026-03-03

### Added

- Fyne GUI installers for Linux, macOS and Windows.
- Manifest-driven installation with strict version pinning
  (`manifest/latest.json`).
- Rocq Platform release selector with the Rocq version shown in the dropdown.
- Doctor interface for post-install diagnostics.
- Workspace generation (`test.v`, `main.v`, `_RocqProject`, VSCode settings,
  opam activation scripts).
- VSCode integration: automatic `vsrocq` / `vscoq` extension install and
  `vsrocqtop` path configuration.
- Headless install support (without `vsrocqtop`).
- Theme aligned with the rocq-prover.org colors.
- GitHub Actions workflows for CI and releases.
